# Governance

Joining the %%DEPLOYED_PRODUCT_NAME%% network does not mean that every participant can run arbitrary analyses against your Client. Defining **what is allowed**, **for whom**, and **under which privacy controls** is a core feature of the Client and the responsibility of its Data Access Managers.

## The Governance menu

The **Governance** menu of the Client brings together the tasks used to control access to local data and to oversee participation in federated analysis:

| Menu item | Purpose |
|---|---|
| [**Trainings**](trainings.md) | Review the federated learning trainings your Client participates in. |
| [**Access Management**](access-management.md) | Define, per cohort and user, how your Client responds to incoming queries and requests: whether they are accepted automatically, rejected automatically, or left for manual review. |
| [**Logs**](logs.md) | Review activity on the Client and investigate issues. |
| [**Notifications**](notifications.md) | Review system notifications and updates requiring attention. |

Incoming statistics, training, and metrics requests are reviewed in the **Requests** menu. See [Requests](../requests/index.md).

Some access controls are also set when the Client is deployed. See [Deployment settings](access-management.md#deployment-settings).
